# 聚类机制假设卡：流—跳跃—流动性联合压力状态

- **策略问题**：单独的卖流、跳跃或流动性指标可能不足以识别“承接突然消失”的联合状态；策略可用该状态收紧风险预算或限定方向信号的适用范围。
- **可观测角色**：5m 主动流方向/持续性、5m 跳跃占比、同纽约本地小时流动性异常；仅使用已完成 bar 与历史统计。
- **聚类对象**：跨时间、跨币种的历史 `(t, asset)` 状态向量，不在每小时仅对 12 个币单独聚类。逐币历史标准化；中心只在 discovery 拟合并冻结。
- **候选输出**：当前实现 `cluster_stress_affinity` 及其短窗口变化、与跳跃或流量的交互。簇号本身不作为有序数值因子；距离的具体语义见[字段知识卡](crypto_cluster_stress_affinity_FIELD.md)。其他状态转移形式仍是待检验假设。
- **预测目标**：先看未来 5m 下行半方差的绝对及市场相对版本；若只预测共同波动，则归类风险 beta。不得先看 holdout 再决定哪个簇是高风险簇。
- **基线**：`micro5_realized_vol` 持续性、三个单变量及其简单门控、纽约时钟。联合状态必须证明增量，而非只拿 silhouette/ARI 或簇均值收益展示。
- **复杂度与失败**：初步仅 K=2/3、固定种子、最小簇占比/币种覆盖；检查发现期两半中心稳定性、验证期占比、跨币广度。可能失败于小簇、单币驱动、中心漂移或波动 beta 重复。
- **接入状态**：已作为版本化状态字段及有界 YAML 模板 `joint_pressure_state` 接入唯一 CLI，采用三阶段筛选和 holdout 防火墙。实证效果以独立的增量信息检查和后续独立时间确认决定；字段实现本身不构成机制有效性的证据。
