# Factor combo 研究与展示标准（2026-09-29）

本标准适用于本仓库从万级挖掘的候选因子进入 5m 时间序列组合、动态权重、信号执行和跨年复核的全部后续工作。生产入口始终是 `python -m src.alpha_mvp.research_cli --config ...`，`mode: factor_combo` 是同一入口中的研究模式。具体实现配置见 `configs/research/crypto_factor_combo_baseline_2023_2025.yaml`；新的研究不可覆盖 `outputs/` 已完成实验。

## 1. 挖掘产物接入合同

- 每个 `factor_sources` 指向已完成挖掘实验的 `selected_factors.csv`，并校验同目录 `manifest.json` 的完成状态、选因子工件名、主时钟、时间序列模式、目标 `entry_lag` 与 `horizon`。清单的两个文件分别记录 SHA-256、实验号、框架版本、时钟、标签口径和来源名次。
- 候选按照上游冻结顺序进入；方向仅从挖掘 discovery 冻结字段读取。combo 的训练段可去数值别名、限制家族数、在线调整非负权重；不能用 `holdout_*` 列重新筛选、调方向或调阈值。
- 原生 5m 与已完成小时因子分别在自身数据时钟计算。小时因子在小时结束后方可进入 5m 面板。在线效用只在原挖掘标签完整成熟后更新，并按其 `entry_lag`、`horizon`、时钟步长计算。输出 `factor_registry.csv` 即本次因子知识卡，逐行列公式、模板、字段、算子、窗口、方向、作用、来源哈希和成熟延迟。
- 新一轮挖掘接入只需更换 YAML 中完成实验的源路径和数量上限。若来源标签或时钟不相容，明确报错；不得静默改用另一来源。

## 2. 组合结构

1. **去冗余**：在训练段标准化后按数值相似性与表达式等价族去重；保留结果和被合并对象记账。
2. **动态因子出入**：每小时根据已成熟残差收益的在线效用、历史长度和稳定性调整非负因子权重，设家族及单因子上限；在 `factor_weights_hourly.parquet` 和 `factor_entry_exit.csv` 中保存出入与权重。
3. **条件变量**：把共同市场 Beta 与逐币残差 Alpha 分开。原生 5m Alpha、小时 Alpha、Beta 形成独立方向贡献；共同风险预测仅缩放预算，不充当方向因子。所有模型报告各部分和消融结果。
4. **多尺度执行**：快、中、慢通道各有 YAML 声明的来源占比、平滑、进入/退出阈值、最短/最长持仓、冷却、调仓间隔和预算。合成仓位是各通道净额，费用按合成仓位的绝对变动精确扣除。机械杠杆诊断要和主组合分列。

## 3. 信号与交易验收

- 决策时点为完成的 5m bar，仓位承担下一根完整 5m 收益。因果自适应尺度以训练期信号分布锚定，后续只利用当前及过去信号更新。进入阈值仅根据 2023 训练段**已自然完成交易数/币/周**匹配预设目标；不看收益，不用 2023 年 3 月或 2024/2025 调参。候选范围达不到目标时明确报告偏差。
- 每条开仓、平仓、调仓事件记录品种、时间、强度、阈值、原因、前后仓位。研究区间末尾强平标为右删失，不计自然完成交易频率和持仓时长分布。报告每币每周交易数、持仓小时均值/中位数/P10/P90、少于 2h 与超过 5d 占比、活跃比例、多空比例、换手和盈亏平衡费用。
- 报告毛/费/净收益、净值、日 Sharpe、最大回撤、交易与日胜率、profit factor、逐币贡献、时段均匀性，并与旧绝对带、静态 combo、纯 Alpha、纯 Beta、等权市场和 BTC 买入持有分开比较。胜率定义及交易口径必须写明；展示频率提升不能代替费后收益改善。
- 首页提供关键指标及年度/交易/逐币导航；年度净值和买入持有分轴；逐币价格、信号强度与阈值、目标与实际仓位、开平仓点、累计收益、持仓和事件表分图展示。不能把不同尺度曲线挤在一张 y 轴上。

## 4. 复核清单

运行单元测试、模拟全入口和有界真实数据。核对 `gross - fee = net`、无未来收益决定当前仓位、训练校准对后期收益不敏感、跨年状态重置、时间成熟边界、来源 manifest 完整性、`holdout_*` 列隔离、报告 HTML 可读性。所有试验输出独立目录并保留配置、源码版本、数据指纹和完整 5m 账本。2023–2025 已见年份是历史复核，不称全新盲测。结论同时报告有效发现与失败、成本和样本限制。
