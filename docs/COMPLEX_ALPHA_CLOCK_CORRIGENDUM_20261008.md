# 复杂Alpha研究时间单位勘误 — 2026-10-08

16:27最终自查发现，universal环境Pandas 3.0.2将格式解析的DatetimeIndex生成datetime64[us, UTC]。原研究直接对asi8使用纳秒常数，没有显式单位转换。2023首三根15m完成时间的整数间隔为900,000,000微秒，而不是900,000,000,000纳秒。

这一行为与[Pandas3.0官方变更说明](https://pandas.pydata.org/pandas-docs/version/3.0/whatsnew/v3.0.0.html)一致：字符串日期默认推断微秒分辨率，整数单位因此可能比旧版小1000倍；官方建议在取整数前用as_unit明确单位。这里的错误属于项目对整数单位的隐式假设，不能靠版本升级后仍通过其他测试来证明采样正确。

影响范围明确如下：R1—R4的coarse/medium没有实现声明的每日UTC相位轮换，而是按误解释的epoch整数近乎固定相位抽样；nonoverlap_incremental_ic没有采用实际H小时间隔，不能当非重叠证据。最终复核v1的非重叠衰减IC也有同一错误，验证期12h/24h相位甚至取不到样本。旧完成实验和九页v1总览不覆盖，阅读时必须联读本勘误。

这不造成未来标签流入训练。标签完整结束与分期清除、OOF幅度校准采用Timestamp/Timedelta比较，不受整数单位误解释影响。原native5价格、资金费、份额/现金财富账本及完整15m预测的条件块bootstrap仍是原固定研究程序的实际结果；但不能称原采样合同已经落实，也不能用错误的nonoverlap数字提升证据等级。1m/5m原料时钟核验使用Parquet本身的纳秒时间类型，已逐币通过；并未将其误差归咎于原始行情。

修正引入complex_alpha_time.py，要求时区已知，统一转UTC后明确as_unit('ns')再取epoch整数。独立测试覆盖s/us/ns三种分辨率、UTC/纽约DST等价、每天6个粗筛和24个中筛点、1/4/12/24h真实间距、NaT/无时区/离网格失败。新runtime.json保存Python/Pandas/NumPy版本与time_contract；冻结文件保存显式时间合同。
